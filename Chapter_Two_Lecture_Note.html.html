1. An Overview of C++

Where it came from

  • Created by Bjarne Stroustrup at AT&T Bell Laboratories in the early 1980s.
  • First called “C with classes”; renamed C++ in 1983.
  • Combines the power of C with object-oriented features (ideas from Simula67).
  • C++ is a superset of C: C++ supports much of C's programming syntax and most C programs can be adapted easily to C++.

What it is used for

  • Operating systems, compilers and new programming languages.
  • Programs for Linux, Windows, Macintosh, Unix and more.

Why use C++?

  • Object-oriented: programs are built from cooperating objects, which gives code reuse and easier maintenance.
  • Portable: the same code can be compiled on almost any computer and operating system.
  • Concise: shorthand symbols keep programs short.
  • Modular: a program can be split across several source files compiled separately and linked together. Changing one file does not mean recompiling everything.
  • Compatible with C: C code can be included in C++ programs.
  • Fast: it is high-level, yet can reach low-level features such as memory addresses.
  • Generic programming: templates and the Standard Template Library (STL) let one algorithm work on different data types.

Challenges

  • C++ is complex. Full use of the STL needs pointers, references, templates and classes.
  • It is performance-centric: the compiler often does not warn you about mistakes such as using an uninitialized variable or an array index out of range.
In plain wordsC++ is like a powerful manual car: fast and flexible, but it trusts the driver. Learn the basics carefully, because C++ will not always warn you when you make a mistake.

2. Anatomy of a C++ Program

Here is the classic first program. Type it into your editor, save it as hello.cpp, compile it and run it.

// First C++ program
#include <iostream>
using namespace std;

int main()
{
    cout << "Hello World!";
    return 0;
}
Line What it does
// First C++ program A comment. The compiler ignores it.
#include <iostream> Preprocessor directive: brings in the input/output library.
using namespace std; Lets you write cout instead of std::cout.
int main() Where the program starts. Every C++ program must have exactly one main().
{ ... } Braces mark the beginning and end of the function body (a block).
cout << "Hello World!"; A statement that sends text to the screen.
return 0; Tells the operating system the program ended normally.
  • Source files are saved with the extension .cpp.
  • Every executable statement ends with a semicolon ;. Directives (#include), main() and braces do not.
  • Every { needs a matching }.
  • return 0; means normal termination; non-zero means abnormal termination. You can also write EXIT_SUCCESS or EXIT_FAILURE (needs #include <cstdlib>). In modern C++ the compiler adds return 0; for you in main.
Old style codeOlder books and compilers use #include <iostream.h> and void main(). Modern C++ uses #include <iostream>, using namespace std; and int main(). If a handout shows the old style, write the modern one.

Statements and blocks

  • Statement: the smallest independent unit, like a sentence in English. It ends with ;. (A period is not used because it would clash with the decimal point.)
  • Block (compound statement): statements grouped inside { } and treated as one unit. No semicolon is needed after the closing brace.
product = number1 * number2 * number3;   // a statement

if (mark >= 50) {                        // a block
    cout << "PASS" << endl;
    cout << "Well Done!" << endl;
}

3. How a Program is Compiled and Run?

The computer understands only machine language, so your source code must be translated. A C++ program passes through six phases:

1 Edit→2 Preprocess→3 Compile→4 Link→5 Load→6 Execute
  1. Edit
    • Type your source code in an editor or IDE and save it as a .cpp file on disk.
  2. Preprocess
    • The preprocessor runs automatically before the compiler and carries out directives such as #include.
    • The result is modified program text with no directives left.
  3. Compile
    • The compiler translates the program into machine code, called object code.
    • The object code has “holes” where it uses library functions (for example, the code behind <<) that are defined elsewhere.
  4. Link
    • The linker fills the holes by combining your object code with the library code.
    • The result is an executable file (for example .exe).
  5. Load
    • The loader copies the executable from disk into memory, together with any shared libraries it needs.
  6. Execute
    • The CPU runs the program one instruction at a time.
In plain wordsThink of translating and publishing a book. The editor is you writing the manuscript. The preprocessor pastes in the pages you referred to. The compiler translates it. The linker binds it together with the reference books it mentions. The loader puts the finished book on the reading desk (memory), and the CPU reads it aloud.
  • The preprocessor, compiler, linker and loader are themselves ordinary programs.
  • Phases 2 to 4 together are the build; phases 5 and 6 are the run.
  • Compiler vs interpreter: a compiler translates the whole program first and produces an executable; an interpreter translates and runs it line by line. C++ is normally compiled.

4. Preprocessor Directives, Libraries and Namespaces

Preprocessor directives

  • A directive starts with # and is handled before compilation.
  • Directives are not statements, so they do not end with a semicolon.
#include <iostream>   // include the input/output library
#include <cmath>      // include the math library
#define PI 3.14159265 // replace the word PI with 3.14159265
  • #include <file> looks in the compiler’s standard folders.
  • #include "file.h" (quotes) looks first in your own project folder, so it is used for your own header files.

Library functions

Library (built-in) functions are ready-made code you can use directly. You include the header that declares them.

Header What it gives you
iostream cin, cout: input and output
cmath (math.h) sqrt(), sin(), cos(), pow(), log()
cstdlib (stdlib.h) Conversions and general utilities
cstring (string.h) String functions: strcpy(), strcat(), strcmp()
cctype (ctype.h) Character tests: isalpha(), isdigit(), toupper(), tolower()
ctime (time.h) Date and time functions
climits Limits of integer types: INT_MAX, INT_MIN, CHAR_MAX

iomanip Output formatting: setw(), setprecision(), setfill()

Namespaces

  • A namespace is a named group of names. It prevents clashes when two libraries use the same name.
  • cout and endl belong to the namespace std. You can write the full name std::cout, or write using namespace std; once and then just cout.
  • You can also pull in one name only: using std::cout;
In plain wordsImagine two students named Abebe in the same class. You say “Abebe from Group A” to tell them apart. The group name is the namespace, and std::cout means “cout from the std group”.

5. Input and Output Streams

  • C++ moves data in streams: sequences of bytes flowing between your program and a device.
  • Input stream: data flows from a device (such as the keyboard) into memory. Output stream: data flows from memory to a device (such as the screen).
  • Both are in the iostream library, so include it first.

cout: output

  • Pronounced “C out”, connected to the screen.
  • cout << data;
  • << is the insertion operator (“put to”).
  • Data can be a string in quotes, a variable, or a value.

cin: input

  • Pronounced “C in”, connected to the keyboard.
  • cin >> variable;
  • >> is the extraction operator (“get from”).
  • Needs a variable to hold the value.
#include <iostream>
using namespace std;

int main() {
    int a, b, c;
    cout << "Enter values of a and b: ";
    cin >> a >> b;            // user types: 10 20
    c = a + b;
    cout << "The result is: " << c << endl;
    return 0;
}
  • The program waits for you to type two numbers separated by a space, tab or new line. Typing 10 and 20 stores 10 in a and 20 in b.
  • Operators can be chained: cout << a << ", " << b; prints both values with a comma between them.
  • endl ends the line (like pressing Enter). "\n" does the same.
  • The compiler chooses the right way to read or print each value from its type.
In plain wordsOutput is the program speaking to you; input is you speaking to the program. The arrows show the direction: cout << points toward the screen, cin >> points toward the variable.

6. Variables and Data Types

A variable is a named storage location in memory that holds a value of one particular type. It has three parts: a name, a type and a value.

Name Value Type
number 123 int
sum -456 int
pi 3.1416 double
average -55.66 double
In plain wordsA variable is a labeled box. The label is the name, the kind of thing the box can hold is the type (a box for whole numbers, a box for decimals), and what is inside right now is the value. You can swap the contents, but you cannot put a decimal number into a whole-number box without it being cut short.

Fundamental data types

  • Integer (whole numbers): char, short, int, long, long long, each signed or unsigned.
  • Floating-point (numbers with a decimal point): float, double, long double.
  • Character: char holds one character in single quotes, such as 'A'. It is stored as its ASCII number ('A' is 65, 'a' is 97, '0' is 48).
  • Boolean: bool holds true or false.
Type Size (typical) Range (typical)
char 1 byte -128 to 127
unsigned char 1 byte 0 to 255
short 2 bytes -32,768 to 32,767
unsigned short 2 bytes 0 to 65,535
int 4 bytes (2 on old 16-bit compilers) -2,147,483,648 to 2,147,483,647
unsigned int 4 bytes 0 to 4,294,967,295
long long 8 bytes about ±9.2 × 10^18
float 4 bytes about ±3.4 × 10^38
double 8 bytes about ±1.7 × 10^308
bool 1 byte true or false

Sizes depend on the compiler and computer. Old 16-bit compilers such as Turbo C++ use 2-byte ints, so the handout table shows smaller ranges. Use sizeof to check your own system. 

cout << "sizeof(char) is " << sizeof(char) << " bytes" << endl;
cout << "sizeof(int)  is " << sizeof(int)  << " bytes" << endl;
cout << "sizeof(double) is " << sizeof(double) << " bytes" << endl;

Signed and unsigned

  • Signed types hold negative, zero and positive values. Unsigned types hold zero and positive values only.
  • Both use the same number of bits, so an unsigned type can hold a maximum about twice as large.
  • Example with only 4 bits: unsigned holds 0 to 15. Signed uses the first bit for the sign, leaving 3 bits, so it holds -8 to 7.

Wrapping around (overflow)

  • If a value goes past the maximum, it does not stop. It wraps around.
  • Unsigned short: 65535 + 1 becomes 0.
  • Signed short: 32767 + 1 becomes -32768.
  • C++ gives no warning. Checking for overflow is your job.
int i1 = 2147483647;   // largest int
cout << i1 + 1 << endl; // -2147483648  (overflow)
In plain wordsThink of a car odometer with 5 digits. After 99999 it rolls over to 00000. An unsigned short does the same at 65535. It is not an error message, just the counter running out of room.

Declaring and initializing variables

  • A variable must be declared before use: DataType name;
  • Each variable can be declared only once.
  • C++ is strongly typed: once declared, an int can only hold integers, never text.
  • Initialization gives a value at the moment of declaration: DataType name = value; 
int myAge;                    // declaration
int num1, num2, num3;         // several of one type
double width = 26.3, area = 0.0;  // declaration + initialization
int length(12), height(5);    // another way to initialize
Careful: garbage valuesA declared but uninitialized variable contains garbage (whatever was in that memory). C++ does not warn you. For example, printing an uninitialized int number; gives an unpredictable value. Always give variables a starting value.

Naming variables (identifiers)

Rules

  • Use letters (a-z, A-Z), digits (0-9) and underscore only.
  • Start with a letter or underscore, never a digit.
  • No spaces or special characters (+ - * / @ $ . ,).
  • Cannot be a keyword such as int, if, return.
  • Case-sensitive: Age and age are different.

Good practice

  • Choose meaningful names: numStudents, not a.
  • camelCase: first word lowercase, later words capitalized: roomNumber, xMax.
  • Single letters only for common uses: x, y, z, and i as an index.
  • Use singular and plural: row and rows.
Reserved keywords (some)

These words have a special meaning and cannot be used as names. All are lowercase.

asm auto break case catch char class const continue default delete do double else enum extern float for friend goto if inline int long new operator private protected public register return short signed sizeof static struct switch template this throw try typedef union unsigned virtual void volatile while

Memory: where variables live

  • RAM is a long sequence of bits (0 or 1), grouped in 8s called bytes.
  • Each byte has a numbered address, like a house number on a street.
  • Declaring a variable reserves enough bytes for its type and gives that place a name.

Scope of variables

The scope of a variable is the part of the program where it can be used. It starts at the declaration and ends at the closing brace of the block that contains it.

  • Global variable: declared outside every function. It can be used anywhere after its declaration.
  • Local variable: declared inside a function or block. It exists only there and disappears when the block ends.
#include <iostream>
using namespace std;

int age = 34;            // global

int main() {
    int age = 14;        // local, hides the global
    cout << age << endl;     // 14
    cout << ::age << endl;   // 34  (:: reaches the global)
    return 0;
}
In plain wordsA global variable is a notice on the school notice board: everyone can read it. A local variable is a note inside one classroom: only the people in that room can see it, and it is thrown away when the class ends.

typedef: your own type name

typedef gives a shorter alias to a long type name.

typedef unsigned short int USHORT;
USHORT width = 9;     // same as: unsigned short int width = 9;

7. Constants and Literals

A constant is like a variable whose value never changes after it is set. It must be given its value when created, and you cannot assign to it later.

const int N = 22;
const double PI = 3.14159;
// N = 30;   // ERROR: cannot change a constant
  • Use constants for values used often but never changed, such as a tax rate.
  • Convention: write constant names in CAPITALS with underscores: MAX_SIZE.
In plain wordsA variable is like a whiteboard that you can rewrite. A constant is like the price printed on a ticket: it is fixed, so nobody can change it by accident.

Enumerated constants (enum)

  • enum creates a group of named integer constants.
  • By default the first is 0 and each next one is 1 more. You can set your own values; the following ones continue counting from there.
enum Color { RED, BLUE, GREEN, WHITE, BLACK };
// RED=0, BLUE=1, GREEN=2, WHITE=3, BLACK=4

enum Color2 { RED2 = 100, BLUE2, GREEN2 = 500, WHITE2, BLACK2 };
// 100, 101, 500, 501, 502
In plain wordsAn enum is a way to give names to numbers so code reads clearly. Writing SUMMER is easier to understand than the number 1.

8. Operators and Expressions

  • An operator is a symbol that tells the computer to perform a mathematical or logical action.
  • The values it works on are operands. Operators can be unary (one operand), binary (two) or ternary (three).
  • An expression combines operators and operands and evaluates to a single value. For example, 3 + 2 evaluates to 5.

Arithmetic operators

Operator Meaning Example
+ - * add, subtract, multiply 2 + 3 gives 5
/ divide 9 / 2.0 gives 4.5
% remainder (integers only) 11 % 3 gives 2
  • Integer division: if both operands are integers, the result is an integer and the fraction is dropped (not rounded). 9 / 2 gives 4, and -9 / 2 gives -4.
  • If either operand is real, the result is real: 9 / 2.0 gives 4.5.
  • Mixed types: the smaller type is promoted to the larger one (implicit casting), so 1 / 2.0 gives 0.5 but 1 / 2 gives 0.
  • Write the multiplication sign: use 2 * a, not 2a.
In plain wordsShare 9 mangoes between 2 people. With whole mangoes only (integer division) each gets 4, and the leftover 1 is the remainder (%). If you cut the last mango in half (real division), each gets 4.5.
// Math: (1 + 2a)/3 + 4(b+c)(5-d-e)/f - 6(7/g + h)
// C++:
(1 + 2*a)/3 + (4*(b + c)*(5 - d - e))/f - 6*(7/g + h)

Assignment operators

  • = means “evaluate the right side and store it in the variable on the left”. It is not mathematical equality.
  • x = x + 1 is valid and common: take x, add 1, store it back in x.
  • Multiple assignment: a = b = c = 36;
Operator Same as Example
+= x = x + 5 x += 5
-= x = x - 5 x -= 5
*= x = x * 5 x *= 5
/= x = x / 5 x /= 5
%= x = x % 5 x %= 5

Relational (comparison) operators

They compare two values and give true (1) or false (0).

Operator Meaning x = 5, y = 8
== equal to x == y is false
!= not equal x != y is true
> >= greater than; or equal x >= 5 is true
< <= less than; or equal y < 8 is false
Common beginner mistake= assigns, == compares. Writing if (x = 5) instead of if (x == 5) compiles but does the wrong thing.

Logical operators

  • && AND: true only if both sides are true.
  • || OR: true if at least one side is true.
  • ! NOT: reverses true and false.
  • Any non-zero value counts as true; only 0 is false.
A B A && B A || B !A
false false false false true
false true false true true
true false false true false
true true true true false 
(x >= 0) && (x <= 100)     // x is between 0 and 100 (do NOT write 0 <= x <= 100)
(x < 0) || (x > 100)       // x is outside 0..100

// leap year: divisible by 4 but not by 100, or divisible by 400
((year % 4 == 0) && (year % 100 != 0)) || (year % 400 == 0)

Increment and decrement

  • ++ adds 1 and -- subtracts 1. a++, ++a and a += 1 all do the same to a.
  • Prefix (++a): change first, then use the value.
  • Postfix (a++): use the value first, then change.
  • The difference shows up only when the result is used in the same statement.
int a = 5, b;
b = ++a;     // a becomes 6 first, then b = 6    (a = 6, b = 6)

a = 5;
b = a++;     // b = 5 first, then a becomes 6    (a = 6, b = 5)
In plain wordsPrefix is “add the coin, then count”. Postfix is “count the coin, then add it”.

Conditional (ternary) operator

A short form of a two-way choice: condition ? valueIfTrue : valueIfFalse

int a = 10, b = 15;
int x = (a > b) ? a : b;     // x = 15  (the larger one)
int min = (m < n) ? m : n;   // the smaller of m and n

Other operators

Bitwise

Work on individual bits. With a = 8 (1000) and b = 3 (0011):

  • a & b = 0000 = 0
  • a | b = 1011 = 11
  • a ^ b = 1011 = 11 (XOR)
  • ~a flips every bit
  • a << 2 = 32 (times 2² )
  • a >> 2 = 2 (divided by 2²)

sizeof

  • Returns the size of a type or variable in bytes.
  • sizeof(int); the result depends on the machine.

Comma

  • Evaluates left, then right, and returns the right value.

Type casting

  • Implicit: the compiler converts automatically. Assigning an int to a double is safe (3 becomes 3.0). Assigning a double to an int drops the fraction (5.5 becomes 5), usually with no warning.
  • Explicit: you ask for the conversion: (double)x or double(x). C++ also has static_cast<double>(x), which is safer.
int sum = 5050;
double average;
average = sum / 100;            // 50.0  WRONG: integer division first
average = (double)sum / 100;    // 50.5  correct
average = sum / 100.0;          // 50.5  correct
average = (double)(sum / 100);  // 50.0  WRONG: the cast comes too late
Why the last one failsBrackets run first. sum / 100 is done as integer division (50), and only then converted to 50.0. The cast must be applied to an operand before the division.

Operator precedence

Precedence decides which operator is evaluated first. Higher in the table goes first. Brackets ( ) override everything.

Level Operators Order
Highest ++ -- (postfix), sizeof, ++ -- (prefix) Right to left
* / % Left to right
+ - Left to right
< <= > >= Left to right
== != Left to right
&& Left to right
|| Left to right
? : Left to right
= += -= *= /= %= ... Right to left
Lowest , Left to right 
a == b + c * d      // evaluated as  a == (b + (c * d))
a == (b + c) * d    // brackets force + first
In plain wordsPrecedence is the “who goes first” rule, just like multiplication before addition in school maths. When in doubt, add brackets. They make the code clearer and cost nothing.

9. Program Formatting and Good Code Style

Comments

  • A comment is text for human readers. The compiler ignores it.
  • // ... single-line comment: to the end of the line.
  • /* ... */ multi-line comment: everything between the symbols.
  • Use comments to state the program’s purpose, explain variables and describe tricky logic. You can also “comment out” code to disable it temporarily.
  • Good comments are shorter and clearer than the code. Too many comments hurt readability, so use meaningful names to reduce the need for them.
c = 5.0/9*(f - 32);   // convert Fahrenheit to Celsius

/* Area of a circle:
   multi-line comment */

Formatting source code

  • C++ ignores extra spaces, tabs and blank lines. They are white space. You must still separate words: int sum, not intsum.
  • Good layout does not change how the program runs, but it makes it far easier to read, for others and for you three days later.
  • Braces: put the opening brace at the end of the line; align the closing brace with the start of the statement.
  • Indentation: indent the body of each block by 3 or 4 spaces per level.
  • Use blank lines to separate sections of code.
#include <iostream>
using namespace std;int main(){cout<<"Hello, world!"<<endl;return 0;}
#include <iostream>
using namespace std;

int main() {
    int mark = 70;
    if (mark >= 50) {
        cout << "You Pass!" << endl;
    } else {
        cout << "You Fail!" << endl;
    }
    return 0;
}

Both work, but only the second is readable. Most IDEs can re-format your code automatically.

Writing good programs
  • Follow conventions so everyone reads code the same way.
  • Use consistent indentation and blank lines.
  • Choose self-descriptive names.
  • Comment important ideas, and write documentation as you code.
  • Avoid hard-to-follow jumps such as break and continue where possible.
  • Use a mono-space font (Consolas, Courier New) in your editor.

10. Programming Errors and Debugging

Errors (bugs) can be found before compiling (by desk checking: reading your own code carefully), while compiling, while running, or after seeing wrong output. There are three kinds.

Syntax (compile-time) error

  • You broke a grammar rule. The compiler finds it and refuses to build.
  • Missing semicolon, misspelled name, undeclared variable, unmatched braces or brackets.
  • Easy to fix: read the message and the line number.

Runtime error

  • The program compiles but fails while running.
  • Dividing by zero, opening a file that does not exist.
  • The program stops early; the compiler cannot warn you.

Logical error

  • The program runs but gives wrong results. The compiler cannot see it.
  • Wrong formula, missing output statement, uninitialized variable, wrong order of statements.
  • The hardest kind to find. Often caused by misunderstanding the requirements.

Spot the errors

cout << "There are four syntax errors here\n
cot " Can you find tem";
Show the four errors
  1. The closing quotation mark is missing in line 1.
  2. The semicolon is missing at the end of line 1.
  3. cout is misspelled as cot in line 2.
  4. The insertion operator << is missing in line 2.

Debugging Techniques

  1. Read the error messages. Do not ignore them; they usually say the line and the cause.
  2. Insert print statements to show intermediate values. Works for small programs.
  3. Use a debugger. The most effective tool: run step by step and watch variables change.
  4. Test with representative cases (typical, boundary and wrong inputs) to expose logic errors.
  5. Advanced tools such as a profiler help find memory leaks and slow functions.
In plain wordsA syntax error is a spelling mistake: the spell-checker catches it. A logical error is a perfectly spelled sentence that says the wrong thing: nobody catches it unless you test it.

12. Worked Programs

Program 1: area of a circle from its diameter

  • Input: diameter d. Process: r = d / 2, then area = π × r × r. Output: area.
#include <iostream>
using namespace std;

int main() {
    const double PI = 3.1415;
    double d, r, area;
    cout << "Enter the diameter: ";
    cin >> d;
    r = d / 2;
    area = PI * r * r;
    cout << "Area of the circle is " << area << endl;
    return 0;
}
A hidden logic error in the handout versionThe handout declares int d, r;. Then r = d / 2 is integer division: a diameter of 5 gives r = 2 instead of 2.5, so the area is wrong. Declaring d and r as double fixes it.

Program 2: Celsius and Fahrenheit

#include <iostream>
#include <iomanip>
using namespace std;

int main() {
    double celsius, fahrenheit;
    cout << fixed << setprecision(2);

    cout << "Enter the temperature in Celsius: ";
    cin >> celsius;
    fahrenheit = celsius * 9 / 5 + 32;      // 9/5*celsius would use 9/5 = 1
    cout << celsius << "C is " << fahrenheit << "F" << endl;

    cout << "Enter the temperature in Fahrenheit: ";
    cin >> fahrenheit;
    celsius = (fahrenheit - 32) * 5 / 9;    // 5/9*(...) would use 5/9 = 0
    cout << fahrenheit << "F is " << celsius << "C" << endl;
    return 0;
}

Why do 9/5*celsius and 5/9*(...) give wrong answers? Because 9/5 and 5/9 are integer divisions (1 and 0). Write 5.0/9, or multiply first.

Glossary for beginners

Source code
The text of a program that you write.
Object code
Machine code produced by the compiler, before linking.
Executable
The final runnable file produced by the linker.
Header file
A file of declarations (such as iostream) added with #include.
Stream
A flow of data between the program and a device.
Identifier
The name of a variable, function or other item.
Declaration
Telling the compiler a variable’s name and type.
Initialization
Giving a variable its first value.
Literal
A fixed value written directly in code, like 43 or "Hi".
Operand
A value an operator works on.
Expression
Operators and operands that evaluate to one value.
Overflow
A result too big for its type, so it wraps around.
Type casting
Converting a value from one type to another.
Scope
The part of a program where a name can be used.
Bug
An error in a program.
